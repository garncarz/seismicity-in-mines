From borehole scans to seismic insight

The goal, the foundations, and the actual state of a machine-learning workflow for mining data

15-20 minute presentation01
Welcome everyone. In this talk I will explain the research problem, the data foundation, the first AI experiments, and what is still missing before this becomes a reliable research result.
01 / The question

Why predict seismicity in a mine?

Mining changes the underground stress field. The rock records those changes as events.

The research ambition is to turn heterogeneous geological and seismic records into earlier, more useful signals.

A practical target

Predict the next seismic events well enough to support interpretation, planning, and risk-aware decisions.

This is a research aid, not an automatic safety guarantee.

Context and motivation02
The central problem is not simply classifying an image. It is understanding how the geological setting and the mining process relate to seismic response. Prediction is the long-term target, but it requires a dependable data foundation first.

03 / From scan to structure

A scan is rich for a human, but opaque to a model

Example input profile: c36-1

Manual logs contain visual boundaries, labels, colors and thin separators.

Digitization aims to produce two useful outputs:

Pixel mask

A class for every image pixel.

Vertical intervals

Consecutive rows collapsed into lithology segments.

Borehole segmentation04
This is the visual core of the current work. A borehole scan contains information that is obvious to a geologist but difficult for software to parse. The first notebook turns visual annotations into training targets; the second notebook learns to reproduce them.
04 / First experiment

Can a vision model extract a structured row?

GPT vision

Few-shot extraction from images, using known examples from C36 and C37 to request a new C38 CSV row.

The prompt asks for coordinates, seam elevations, thicknesses, rock statistics and strength values.

What the comparison found

Several fields were shifted or incorrect. For example, columns L/M, P/Q, and AE-AQ disagreed with the expected row.

No aggregate accuracy metric is calculated yet. The result is a prototype, not a validated production extractor.

Multimodal CSV extraction05
The scan-to-CSV experiment is useful precisely because it exposes the risk. A language model can return a plausible-looking row while placing values in the wrong columns. At this stage, field-by-field comparison is more informative than claiming a success rate we have not measured.

The model sees three channels: grayscale intensity, vertical gradient, and horizontal gradient.

Random 768 x 192 patches, flips, and brightness/contrast augmentation provide the training material.

Six lithological classes06
The segmentation model uses six classes. The extra gradient channels help expose boundaries, not just color or intensity. Since the scans are tall, training uses patches and prediction uses overlapping windows with blending to reduce visible tile seams.
06 / Model design

Small enough to iterate, structured enough to learn boundaries

Input
3 channelsIntensity + vertical and horizontal gradients
Encoder
3 blocksPooling, convolutions, group normalization and GELU
Decoder
Skip connectionsInterpolation restores spatial detail
Output
6 classesWeighted cross-entropy + soft Dice loss

Training recipe

AdamW | learning rate 3e-4 | weight decay 1e-4 | 15 epochs | seed 42

Inference

Overlapping sliding windows, 384 px vertical stride, 96 px horizontal stride, Hann-like blending

Compact U-Net-style architecture07
The design is deliberately compact. The work is still exploratory, so iteration speed matters. The loss combines class-weighted cross-entropy with soft Dice loss, balancing per-pixel learning with overlap quality.

Metrics from the recorded notebook run08
The strongest result is coal, with IoU about 0.919. The overall mean IoU is about 0.514, and the class breakdown shows why that average must be read carefully: claystone is not learned, and background IoU is very low. These are useful diagnostics, not a finished benchmark.
08 / What can go wrong?

Good-looking output is not the same as geological truth

01

Small sample

Only six scan/annotation pairs. Validation has two images.

02

Class ambiguity

Thin black separators are preserved as coal; claystone is absent from the prediction.

03

Scale gap

JSON intervals are pixel rows, not metres. Depth calibration is not implemented.

The key methodological lesson

Validation must test transfer to new profiles, not only performance on familiar visual patterns.

Limitations are part of the result09
This slide is important for scientific credibility. The model can be useful as a digitization assistant, but the current evidence cannot support broad geological or safety claims. Generalization, calibration, and uncertainty are the next evaluation problems.
09 / Current state

What exists today, and what does not

Working

Data loading and preprocessing across image, spreadsheet and geospatial formats.

U-Net training, full-image prediction, overlays and JSON interval exports.

Neural-network and transformer experiments for the broader seismicity objective.

Still open

More labelled profiles and profile-level validation.

Depth calibration, uncertainty estimates and systematic extraction metrics.

Linking geological outputs to temporal and spatial seismic-event prediction.

A prototype with a functioning research loop10
The project has crossed the threshold from idea to functioning research loop: data can be loaded, models can be trained, predictions can be exported, and maps can be produced. The open work is now about trustworthy evaluation and integration.

Roadmap11
The roadmap is intentionally staged. More complex models are less urgent than better labels, profile-level validation, and physical calibration. Once those foundations are stable, geological features can be connected to the seismic prediction models described in the README.
